# Canonical fixture contract: `shadowed-lut-v1`

## Purpose

Prove that ColorTrace can identify hidden runtime color-resource drift, calculate exact affected and safe scope, and verify targeted simulator recovery without hidden answers or hardcoded diagnosis.

## Topology

- Two synthetic workers (`worker-a`, `worker-b`)
- Six successful render jobs across multiple shots/frames
- Three affected source jobs/frames
- At least one verified-safe job on `worker-b`
- At least one downstream derivative of an affected render
- One plausible non-causal distractor signal
- A real Grafana alert generated by fixture telemetry

Exact job IDs and placement may be permuted in hidden test variants while preserving these constraints.

## Color mechanism

Both workers load byte-identical nominal `config.ocio` files. The config references an external LUT. Different allow-listed runtime context/environment/search-path resolution causes one evaluated transform on `worker-b` to resolve a stale/shadowed LUT with a different content digest. Jobs not consuming that transform remain safe, including one on `worker-b`.

The fixture uses real OpenColorIO processing and a structurally valid config. `ociocheck` output is recorded but is not the visual correctness oracle.

## Images and references

Source imagery is procedurally generated or expressly licensed, visually legible at demo resolution, and recorded in `fixtures/provenance/`. Approved golden outputs are generated under the declared good runtime state. Candidate/reference comparison uses a versioned OpenImageIO-based deterministic policy and stores metrics plus a difference artifact.

## Telemetry

Each job emits correlated Prometheus-compatible metrics, Loki logs, and OpenTelemetry traces suitable for Tempo. Required fields include trace/job/worker/shot/frame IDs, status, config digest, resolved resource digests, transform identity, manifest/artifact digests, timing, and safe error metadata. The stale-LUT cause is inferable from this operational evidence but ground-truth labels are absent.

## Lineage and oracle

A separate deterministic oracle defines source-to-render and render-to-derivative lineage, causal transform/resource use, affected set, safe set, and expected recovery result. It is accessible only to fixture evaluation, never the agent, MCP responses, runtime API, prompt, or product UI.

## Required variants

- canonical placement;
- worker/job/shot permutations;
- missing trace span;
- delayed telemetry;
- MCP timeout/error;
- missing resource manifest;
- same worker with mixed affected/safe jobs;
- visually similar but hash-different non-causal resource where comparison remains safe;
- recovery success and recovery failure;
- duplicate action/task delivery.

## Determinism

Generation is seed-controlled. Tool/container versions, source generation, config/LUT bytes, manifest schema, reference policy, lineage, and oracle digest are pinned. The same seed and versions must reproduce artifact digests or explain platform-normalized exceptions.

## Legal boundary

No proprietary film frames, studio configs, interview material, real telemetry, trademarks presented as affiliation, or ambiguously licensed LUTs are included. Every distributable asset has source, author/generator, license, modifications, and digest in the provenance ledger.
